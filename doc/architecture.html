LCRD · Hard-Isolation · Architecture

LCRD 架构详解

一句话：LCRD 是一个“外生校验的 agent 任务协议 + 带门禁的提示词策略演化层”。它让模型遵守任务契约，也让 skill 变更有版本、有证据、可回滚；它不是权重 RSI，也不是通用 agent 产品。

runtime protocol policy evolution exogenous verifier headroom + detectability no new session events prompt-level only

1. 定位与边界

LCRD 有两层，刻意不混在一起：

运行时协议

控制一个任务：根锚、声明计划、外生校验、失败回退、重试上限、终止转人工、可选学习轮。

策略演化

控制后续任务可用哪些 skill：提案、静态扫描、holdout 门禁、预审、审批、在线监控、hard-out 审计。

证据与运维

flow 导出、dataset/DPO、策略账本、被拒提案反馈、通知、运行时 invariant。

非目标：不改模型权重；不执行 skill 代码；不让模型写校验结果/门禁结果/指针/审批；不新增 session 事件类型。权重路线是独立管线，当前只有 DPO 导出、评测底座、训练脚手架和 checkpoint registry，没有已跑通的训练结果。

所有状态迁移在注册的监听器里，而不是提示词里。门禁子进程以 evolveEnabled: false 挂载候选版本，因此测量运行不会产生提案。

4. 运行时协议

4.1 根锚

用户第一条消息是任务契约。根锚文本作为固定 system-prompt 段落注入；模型不能扩张、重定义或静默缩小主任务。根锚内出现矛盾时，模型只能在顶层边界内权衡。

4.2 声明

任务工具调用前必须调用 lcrd_plan：

{
  goal: string,
  stop_condition: string,
  feasibility: boolean,
  verifier: { kind: "assert", conditions: string[] }
          | { kind: "python", checks: string[] }
          | { kind: "llm" }
}

声明是数据；是否可行、如何校验、是否通过由引擎决定。没有声明就调用任务工具会被阻断。

4.3 回退与终止

校验失败时结果被拒绝并返回原因；模型必须换一种方法重新声明，禁止原样复用失败计划。连续失败达到 maxRetries 后终止，后续工具调用被拦截，任务转人工。新的真实用户命令重新开启任务边界，重置计划/失败计数/学习预算/终止状态。

4.4 校验器

kind模型提供执行
assertconditions: string[]受限 JS 表达式，读取 result/content/isError；必须引用其一、不可恒真、全部为真才通过；工具错误直接 FAIL。
pythonchecks: string[]固定 Python 模板求值，注入 json；规则同 assert；超时/启动失败判 FAIL。
llm无独立会话、固定提示词、温度 0；非 JSON / 非 PASS 一律 FAIL；每次多一次 API 调用。

assert 的表达式语法是 src/expr.ts 的受限子集：比较、布尔、typeof/in、属性读取和白名单只读方法；this、函数构造、正则字面量、动态 import、循环不可表达。校验器不执行模型提供的代码。

4.5 文件式任务流

fileFlowEnabled 适合只有 bash 与字符串替换编辑器的极简部署：插件创建并固定 taskflow-<uuid>/，模型维护 task.md、subtasks/、progress.md；任务目录只放流程文件，产物写 workspace；越界写入计入 path violation，达到上限终止。标准部署保持关闭，使用纯上下文回退流。

5. 策略演化

propose ──► static scan ──► stage version ──► gate
                                              │
              ┌───────────────────────────────┴───────────────┐
              │ probe candidate mount                          │
              │ baseline runs ──► headroom check               │
              │ candidate runs ──► missing-reward check        │
              │ paired metrics / CI / detectability            │
              └───────────────────────────────┬───────────────┘
                                              │
                     pass? ──► brief ──► approval ──► promote
                       │                               │
                       ├─ no-gain / gate-failed ──► rejected-edits
                       └─ instrument abort ──► gate-aborted report

演化默认关闭，开启需要 evolveBenchmarkDir 和 @deepseek-ai/dsh-skill。候选的 skill 正文是模型写的文本；静态扫描在版本落盘前拦截注入、身份否定、越权、隐藏文本、伪造框架和 holdout 泄漏。rules+llm 追加一次独立固定提示词扫描。

5.1 版本与门禁

通过的提案写入不可变 versions/vNNNN/，包含 manifest、父版本、理由、benchmark digest、skill digest。门禁顺序：

  1. 候选挂载探针：没有 run.json 直接中止，不烧完整预算；探针只验证挂载，不评分。
  2. baseline 在抽中的 holdout 子集上运行；每个 run 独立 workspace，fixture 复制进 workspace。
  3. baseline 聚合后检查 headroom = 1 - baseline.rewardRate：小于 evolveMinGain 时写 baseline-only report 并以 gate-aborted 返回，candidate 不启动。
  4. candidate 运行；admission: reward 下任何缺失 reward 都是不完整证据，不静默丢对。
  5. 配对统计、token/终止/作弊/hook/路径指标、detectability；写 report/gain-report/brief。
headroom 与 detectability 不同：detectability 是样本能分辨的最小增益；headroom 是基准理论最大增益。样本再大，headroom 不足也无法测出 evolveMinGain。

5.2 指标与判定

指标含义
rewardRate任务 reward 命令的均值；admission: reward 的唯一准入指标
passRateagent 自证通过率，仅诊断，不作 ground truth
terminatedRate未达成奖励的终止率；零容忍策略阈值，不是显著性检验
cheatRatespeculative_cheat 松弛 / 计划数；零容忍策略阈值
hookInterceptions, pathViolations策略 hook 拦截与文件流路径越界
tokenstoken 花费；相对基线的回退受 evolveMaxTokenRegression 约束
detectabilityz * sd(deltas) / sqrt(n)；样本分辨力
headroom1 - baseline.rewardRate；最大可能增益
meanDelta / CI配对 c baseline/candidate 差值与 bootstrap 区间；verdict 与 gate 决定分离

判定结果：gain / no-gain / insufficient-evidence。evolveSignificance 默认 off；bootstrap 额外拒绝区间包含 0 的 reward 增益，并要求 admission: reward + 至少两对样本。evolveRequireDetectability 默认 true：样本无法分辨 evolveMinGain 时拒绝准入。

报告与 store：report.json（含 outcome、detectability、pairedN）、gain-report.md/json、brief.md/json；baseline-only abort 的 brief 显示 ABORTED — candidate was not run。

5.3 审批、监控与审计

  • evolvePromote: approval（默认）询问审批服务，只有 allowed-once promote；auto 只用于 CI。
  • promote/rollback 写 policy-events.jsonl，通过既有 additionalContexts 发通知，不新增 session 事件类型。
  • 在线监控把已完成 run 折叠到当前版本的分数窗口；首个完整窗口作为该版本基线，后续若 cheat/终止率回退则退回父版本并写 quarantine.json。
  • hard-out 是封存审计，按 evolveHardoutAuditEvery 与父版本在同一批任务上对照；回退会设置 promotionHeld。
  • 被拒提案写 rejected-edits.jsonl；下一次提案读取最近记录，反馈是 best-effort。

7. Dataset 与 DPO

datasetExport: run 在 run 结束时追加：

文件内容
dataset.jsonl每个协议事件一行，含 task_group、failureClass、infraFailure、trainability 与记录字段
relaxations.jsonl失败后放松检查的声明，含前后表达式、轴、cause、relax_type
runs.jsonlrun 级元数据：插件/协议/模型/平台/策略版本
dpo.jsonlprompt/chosen/rejected/meta；chosen 是恢复放松前检查的合成侧
trainable.jsonl / needs_review.jsonl按 trainability 分流；infra 失败只留在全量流
DPO 的边界：dpo.jsonl 主要教“不要弱化校验”，不是任务能力提升。要做能力权重路线，需要成功轨迹/奖励数据与独立评测；当前数据量、GPU、open-weight 模型都不在仓库内。

pnpm run lcrd:audit -- --dataset <corpus> --benchmark <dir> 先统计 pair、group、泄漏、trainability、DPO 形状。pnpm run lcrd:dpo 只做 session log 对齐/DPO 导出，不是训练器。

8. 权重路线

P0 数据审计

lcrd:audit：counts、trainability、DPO 形状、task group、benchmark 泄漏；无 GPU。

P0 评测底座

lcrd:weight-eval：runner 无关的 base/candidate 评测，独立 workspace + reward；不内置模型。

P1 训练脚手架

training/prepare_dpo.py 按 group 切分；training/train_dpo.py QLoRA DPO；需要 open-weight 模型+GPU。

P2 checkpoint 控制面

lcrd:checkpoint：不可变 manifest、eval 证据、promote/rollback；与 skill policy store 分离。

没有“在线 RSI 训练循环”，没有在 agent 内执行训练，没有 API 模型的权重更新。正确顺序：数据审计 → 训练 → 独立 held-out eval → checkpoint register/promote；任何一步没有证据都不应进入下一步。

10. 安全与信任边界

  • Skill 是数据：不能写门禁结果/指针/审批；静态扫描是启发式，真正防线是数据化 + 外生校验 + 人工 promote。
  • Benchmark/reward 是运维可信：reward 以 shell: true 在隔离 workspace 运行；candidate 看不到其他 run 的产物。
  • Holdout/hard-out 隔离：部署责任；必须在模型可读根之外；插件只校验不在 skill 根内。
  • 无新 session 事件：通知/切换走既有 tool-result/additional-context；策略记录只在 store。
  • 无任意代码执行：assert 是受限表达式；不提供模型可指定的 command 校验器；训练不在 agent 内启动。
  • 默认 approval：统计证据不足时不要 auto；detectability/headroom 先过线。

11. 测试与质量门禁

当前包测试覆盖协议、校验器、学习、演化、门禁、store、隔离、dataset、报告、拒绝反馈与脚本底座：

pnpm exec vitest run packages/experimental/lcrd
pnpm exec vitest run packages/experimental/lcrd --coverage   # per-file 100%
pnpm run doc-typecheck
pnpm exec oxlint .
pnpm run test:docs

门禁重点：detectability 在噪声地板内；headroom 足够；missing reward 不静默丢对；baseline-only abort 写 report；propose 区分 gate-aborted/gate-failed；rejected-edits 有界；权重 registry 与 skill store 分离。

12. 限制与路线

  • 提示词层上限：skill 只能买来 prompt 能买到的能力；权重是另一条闭环。
  • 统计功效：默认 5×3 小样本；显著性默认 off；先跑 noise 再决定。
  • 基准饱和：基线过高时 headroom 不足，应该换有失败空间的任务，而不是继续调 skill。
  • 缺 reward 的 run 是仪器失败，不是 0 分；先修数据/挂载，再跑门禁。
  • 在线 RSI 未实现；权重训练需要 open-weight + GPU；当前只有 scaffold。
  • 配置目录生成器在 Config 移到 config.ts 后把 lcrd 归为 library；这是独立文档工具问题。
