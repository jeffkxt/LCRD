1. 定位、边界与不变量

LCRD（long-chain reasoning drift）是一个运行在 harness 扩展点上的插件。它有两个独立闭环：

运行时协议

控制一个任务：根锚、声明计划、外生校验、失败回退、重试上限、终止转人工、可选学习轮、文件式任务流。

策略演化

控制后续任务可用哪些 skill：提案、静态扫描、不可变版本、holdout 门禁、预审、审批、在线监控、hard-out 审计。

证据与运维

flow 导出、dataset/DPO、策略账本、拒绝反馈、通知、invariant、权重路线脚手架。

1.1 核心不变量

  • 模型只写声明、skill 文本、rationale 和校验表达式；它不写校验判定、门禁结果、策略指针或审批结果。
  • skill 是数据，不是可执行代码；静态扫描只做启发式过滤，真正防线是外生校验、数据化与人工 promote。
  • promote 是一次指针 CAS + skill 注册集替换；下一个任务重新读取 current.json。
  • 策略生命周期只写策略根目录，不新增 session 事件类型；不加载 LCRD 的构建不会遇到未知事件。
  • 运行时与演化都靠注册的监听器执行，不靠提示词自律；门禁子进程加载候选时关闭演化，测量运行不能发起提案。

1.2 明确的非目标

  • 不改模型权重；不训练 API 模型；不执行 skill 中的任意代码。
  • 不替代通用 agent 产品；它是一层协议/门禁/审计插件。
  • 不保证 prompt skill 一定带来增益；它只保证“不经过证据不得 promote”。
  • 不提供模型可指定的 command 校验器；assert 是受限表达式，python 是固定模板。

4. 运行时协议

4.1 根锚

用户第一条消息是主任务契约（根锚）。根锚文本作为固定 system-prompt 段落注入，包含全部约束（预算、时间、合规等）。模型无权扩张或重定义主任务；主任务未明确要求的操作视为越界。根锚内部有矛盾时，模型只能在顶层边界内权衡，任何输出不得违背约束。

4.2 lcrd_plan 与声明期门禁

lcrd_plan({
  goal: string,
  stop_condition: string,
  feasibility: boolean,
  verifier:
    | { kind: "assert", conditions: string[] }
    | { kind: "python", checks: string[] }
    | { kind: "llm" }
})
  • 先声明后行动：任务工具调用前必须有当前计划；没有计划的任务工具会被阻断。
  • 条件必须可编译并引用 result/content/isError 至少之一；空列表在声明期被拒，到达校验器也判 FAIL。
  • 区分度：条件不能在全部探测输入上恒真；恒真/未绑定/无法编译在声明期被拒，不会成为生效检查。
  • presence-only（可选）：只断言存在/类型/非空、不钉字面量也不读结构化字段的声明会被拒绝。
  • hold-rate 上限（可选）：声明在探测矩阵上的最大通过率不得达到 declarationMaxHoldRate。
  • 重复失败计划：校验失败后原样重申同一计划会被拒绝；新的用户命令或后续一次通过会清除指纹。
  • stop_condition 语义：核心不解析它与校验器是否一致；这属于 checkPlan hook 的判断。

4.3 三种校验器

kind模型提供执行与判定成本/风险
assertconditions: string[]受限 JS 表达式读取 result/content/isError；全部为真才 PASS；工具执行失败直接 FAIL。无额外 API；语法受限，不能执行任意代码。
pythonchecks: string[]插件固定 Python 模板执行表达式，注入 json；规则同 assert；超时或无法启动判 FAIL。需要系统 python；每次启动解释器。
llm无独立会话 + 固定提示词（根锚 + goal/stop_condition）+ 温度 0；非 JSON 或非 PASS 一律 FAIL。每次多一次独立 API 调用；隔离靠会话/提示词，不靠跨账号。

assert 的表达式语法：比较、布尔逻辑、typeof/in、属性读取、白名单只读检查方法。不可表达 this、函数构造、正则字面量、动态 import、循环；因此条件不能触达宿主进程或阻塞事件循环。失败原因会带实际类型/改写提示。

4.4 失败、回退、终止

  • 校验失败：结果被阻断，模型看到失败原因；同一计划不能原样重试，必须换方法。
  • maxRetries：连续失败达到上限后终止，后续工具调用（包括 lcrd_plan）被拦截，任务转人工。
  • failedCheckConsumesRetry: false：引擎拒绝模型检查（invalid-condition/eval-error）改由自己的 invalidChecks 计数限制，任务预算只度量真实步骤结果。
  • hook 的 deny/block/抛错独立计数，同样以 maxRetries 为上限；deny 清除旧计划，防止沿用绕过。
  • 终止是安全边界，不是统计结论；2 vs 0 的终止差可以是策略拒绝理由，同时 Fisher 精确检验不显著。

4.5 学习模式

learningEnabled 开启后，连续校验失败达到 learningThreshold 时暂停直接重试，进入最多 maxLearningAttempts 轮的学习：

  1. 声明：lcrd_learn 给出问题分析、所需知识、学习方法、自评标准。
  2. 获取知识：只有 learningTools 白名单工具放行；任务工具与 lcrd_plan 在学习阶段被拦截。每个工具调用登记为可引用证据（路径/URL、摘要、片段，编号 e1…e20）。
  3. 自评：lcrd_learn_verify；没有学习工具调用或没有引用证据的通过判定会被拒绝且不消耗轮次；自评失败消耗一轮。
  4. 重解：自评通过后重新 lcrd_plan 并执行；结果仍走外生校验。通过则任务完成并重置学习预算；失败消耗一轮并回到学习模式。

学习只影响当前上下文，不持久化、不跨会话复用。学习期间 maxRetries 终止被挂起，由学习轮预算管辖；关闭学习后回到旧的连续失败终止行为。注意：如果 learningThreshold 大于 maxRetries，普通重试可能先终止。

4.6 文件式任务流（fileFlowEnabled）

适用于只有 bash 与字符串替换编辑器的极简部署。开启后：

  • 插件创建并固定 <task-flow root>/taskflow-<uuid>/，目录名与 flow 日志目录刻意不同；模型不创建、不命名它。
  • 目录初始为空；模型必须创建 task.md、subtasks/、progress.md。读取日志/目录不能代替创建。
  • 任务目录只放流程文件；任务产物（脚本/代码/数据）必须写 workspace，写入任务目录会被引导性拒绝。
  • task-flow/ 内的路径必须停在当前任务目录；读写其他任务目录/裸根会被拒绝并计数，达到 fileFlowPathViolationsMax 终止为严重幻觉。
  • 受守卫的是 fileFlowTools 的写入操作；读操作放行；shell 命令路径目前不检查。
  • workspaceRoot 注入协议文本；回退顺序：session cwd → sandbox workspaceRoot → DSH_CWD → fs backend 工作根。部署工作区不同请显式设置。
  • 协议段要求模型执行 shell 前先 cd 到 workspace。

5.1 提案与静态扫描

  • lcrd_propose 参数：rationale、parent_version、skills[]（name/description/content）。
  • parent_version 必须来自引擎给出的候选集（当前版本恒在候选内）；只有 promoted 版本可作为基线。
  • 每次任务边界最多 evolveMaxProposals 个提案；一个提案最多 evolveMaxSkills 个 skill，每个正文最多 evolveSkillMaxBytes，rationale 截断到 evolveRationaleMax。
  • 静态扫描（在版本落盘之前）：注入措辞、身份否定、越权（跳过校验器/重定义根锚/改预算/调用提案）、隐藏文本（零宽、bidi、编码块、指令 HTML 注释）、伪造框架标签、holdout/hard-out 泄漏。
  • evolveStaticScan: rules+llm 追加一次固定提示词模型扫描；输出不可用按 block 处理。evolveScanModel 应独立于提案模型。
  • 静态拒绝写 rejected-edits.jsonl stage static-scan，版本目录不创建。

5.2 门禁流水线

  1. Stage：不可变 versions/vNNNN/，manifest 记录 parent、rationale、benchmark digest、skill digests、status proposed。
  2. Probe：候选挂载一次，只验证 child 产出 run.json；不评分、不执行 reward。失败直接配置错误中止。
  3. Baseline：在抽中的 holdout 子集上运行当前版本；每 run 独立 workspace，fixture 复制；reward 在 workspace 内。
  4. Headroom：baseline 聚合后 headroom = 1 - rewardRate；headroom < evolveMinGain 写 baseline-only report，outcome: gate-aborted，candidate 不启动。
  5. Candidate：运行候选；任何缺失 reward 都是不完整证据，baseline 缺失在 candidate 前中止，candidate 缺失写完整中止 report。
  6. Metrics：配对 delta、bootstrap CI、detectability、token、终止、cheat、hook、path。
  7. Reports：report.json（outcome/detectability/pairedN）、gain-report.md/json、brief.md/json。

候选必须同时满足：增益 ≥ evolveMinGain；终止率回退 ≤ evolveMaxSafetyRegression；cheat 回退 ≤ evolveMaxCheatRegression；hook/路径不增加；token 回退 ≤ evolveMaxTokenRegression；样本能分辨门槛（evolveRequireDetectability）；benchmark digest 未变；预算未耗尽。任何一项失败都写报告并拒绝。

5.3 审批与 promote

  • evolvePromote: approval（默认）询问审批服务；只有 allowed-once promote。
  • interaction: auto 映射审批策略 never，无人值守只能提案。
  • evolvePromote: auto 只用于 CI；它绕过人工，但仍需通过门禁/headroom/detectability/显著性配置。
  • promote 是 pointer CAS + skill 注册集替换；manifest 状态变 promoted，另一个版本可能成为当前。
  • 审批被拒/审批服务缺失：版本保持 gated-passed，可离线 promote。

5.4 在线监控与 hard-out

  • 每个已完成 run 折进当前版本的分数窗口；窗口大小 evolveRollbackWindow。
  • 版本自己的第一个完整窗口成为在线基线；后续窗口若终止率回退超过 evolveRollbackMargin 或出现 cheat 回退，指针退回 parent，写 quarantine.json。
  • 线上 run 永不与 holdout 指标比较（分布不同）；监控只看同版本窗口。
  • hard-out 是封存审计：每 evolveHardoutAuditEvery 次 promote 一次，与 parent 在同一批 sealed 任务上对照；回退设置 promotionHeld，阻止后续 promote 直到运维清除。
  • hard-out 永不参与日常门禁；它只在 promote 后周期性审计。

5.5 通知、账本与拒绝反馈

  • promote/rollback 写一行 [SYSTEM NOTICE] LCRD Policy Promoted|Rolled Back: ...，通过既有 additionalContexts 在下一次工具决策交给模型；不新增 session 事件。
  • policy-events.jsonl 与 current.json 是权威记录；通知是 best-effort，会话立即结束可能收不到。
  • recorder 把 live active version 冻结进 run.json.policy_version；下一个任务重新读取 current.json。
  • 静态拒绝、gate 失败、gate 中止写 rejected-edits.jsonl（schema 1）；下一次提案读取最近 3 条，只读最近 20 条；坏行/IO 失败不阻塞提案。
  • quarantineHints 继续从 quarantine.json 提供；与被拒记录分开呈现。

6. 门禁指标与判定

6.1 抽样、隔离与 reward

  • 三层基准：train.jsonl 供模型提案；holdout/*.jsonl 供门禁抽签；hardout/*.jsonl 只供封存审计。
  • 轮换：每次抽 evolveHoldoutSize 个 holdout，最近 evolveHoldoutCooldown 次抽中的任务暂时不合格；pool 不够会响亮失败。
  • 隔离：每 run 使用 runs/<side>/<task>-<repeat>/workspace；有 fixture 时复制到 workspace 根，否则空目录；child cwd 与 LCRD_RUN_WORKSPACE 指向它；reward 也在那里运行。
  • reward 信任边界：benchmark 是运维可信产物；reward 以 shell: true 在 workspace 执行。数字优先（0–1），否则 exit 0 = 1，其他/超时/启动失败 = 0。
  • probe：只验证候选挂载产出 run.json，每个 gate 只跑一次，不评分、不执行 reward。
  • missing reward：admission: reward 下任何 null reward 都视为不完整证据；不再静默从配对中丢弃。
  • digest：门禁前后重算 benchmark digest；中途改文件则本轮作废。

6.2 headroom / detectability / 显著性

概念公式/含义不满足时
detectabilityz(1-alpha/2) * sd(paired deltas) / sqrt(pairedN)；样本能分辨的最小增益evolveRequireDetectability: true 时拒绝准入；提示增加 repeats/holdout 或降低 minGain
headroom1 - baseline.rewardRate；基准还能体现的最大增益baseline-only report，gate-aborted，candidate 不启动
minGain绝对增益门槛；admission: reward 用 rewardRate，self-report 用 passRate门禁失败（gated-failed）
significanceoff 或 paired bootstrap；bootstrap 要求 reward + ≥2 pairs；CI 包含 0 时拒绝gate 失败，reason 含 not significant
alpha双侧错误率，默认 0.05；同时影响 detectability 与 bootstrap配置必须 0 < alpha < 1；否则配置错误
两者不能互相替代：detectability 小但 headroom 小（例如基线 0.95），或 headroom 大但样本太吵，都不能支撑 promote。先跑 lcrd:policy noise，再定 minGain/holdoutSize/repeats。

6.3 决策树与 report 字段

budget aborted? ──► gate-aborted (token/wall)
benchmark digest changed? ──► gated-failed (void)
detectability > minGain and requireDetectability? ──► gated-failed (insufficient evidence)
reward gain < minGain? ──► gated-failed
termination/cheat/hook/path/token regression? ──► gated-failed
significance bootstrap CI includes 0? ──► gated-failed
otherwise ──► gated-passed (then approval)
instrument precondition fails (headroom/missing reward) ──► gate-aborted (baseline-only or full report)
report 字段含义
outcomegated-passed / gated-failed / gate-aborted；与 manifest 状态一致
pass / reasons门禁决定与逐条原因
baseline / candidate聚合指标；baseline-only abort 时 candidate.runs = 0
detectability / pairedN / minGain样本分辨力、配对样本数、门槛
samples每个 run 的原始行，报告不丢原始证据
selectedTasks / repeats / benchmarkDigest抽签与基准身份，支持审计复算

gain-report.json 另含 paired rows、meanDelta、ciLow/ciHigh、verdict、token、detectability；brief 只列异常项。baseline-only abort 的 brief 显示 ABORTED — candidate was not run。

8. Dataset / DPO / 归因

文件内容与用途
dataset.jsonl每个协议事件一行，含 step/ts/task_group/failureClass/infraFailure/trainability 与记录字段。
relaxations.jsonl失败后放松检查的声明；含前后表达式、轴、cause、relax_type；只有 speculative_cheat 被门禁/监控惩罚。
runs.jsonlrun 级元数据：插件/协议版本、模型、provider、平台、cwd、耗时、最终判定、策略版本。
dpo.jsonlprompt/chosen/rejected/meta；chosen 是恢复放松前检查的合成侧，meta 带 synthetic、repair、轴。
trainable.jsonl / needs_review.jsonl按 trainability 分流；infra 失败只留在全量流。
anchor-judge.jsonl锚点与声明的 within/outside 判定请求。

导出：datasetExport: run 在 run 结束（disposal）时把该 run 追加到 datasetDir；lcrd:dpo 可把 session log 与语料对齐并导出 DPO。文件级导出需要 session log，进程内导出不需要。

trainability：trainable 是引擎确定性标签（上下文行、通过判定、invalid check 等）；needs-review 需要人或 LLM 判别（honest-mismatch、llm-stop-unmet、python-check-failed、tool-isError、unclassified）；discard/infra 失败只进入全量流。

归因：默认日志启发式把 verdict/exception/verifier 映射到 FailureClass，把放松声明映射到 RelaxationCause 与 Trainability。attributionModule 可用领域 bundle 替换三个分类函数；不完整/非法 bundle 在启动时响亮失败。

DPO 的边界：当前 DPO 主要教“不要弱化校验”，不是通用任务能力；要提升任务表现需要成功轨迹/奖励数据与独立评测。合成 chosen 不等于真实人类偏好。

9. 权重路线（P0/P1/P2）

权重路线与提示词门禁分离，当前是脚手架 + 评测底座，不是已跑通的训练结果。

P0 数据审计

lcrd:audit 统计 corpus 文件、行数、invalid、trainability、DPO 形状、group、benchmark 泄漏；无 GPU。

P0 评测底座

lcrd:weight-eval 用任意 runner 跑 base/candidate；每任务独立 workspace + fixture + reward；不内置模型。

P1 训练脚手架

training/prepare_dpo.py 按 group 切分；train_dpo.py QLoRA DPO；需要 open-weight 模型 + GPU。

P2 checkpoint 控制面

lcrd:checkpoint 注册不可变 manifest/eval、list/show/promote/rollback；与 skill policy store 分离。

没有在线 RSI 训练循环，没有 agent 内训练，也没有 API 模型的权重更新。正确顺序：数据审计 → 训练 → 独立 held-out eval → checkpoint register/promote。任何一步没有证据都不进入下一步。

10. 全部配置参数

以下字段来自 src/config.ts 的 Config interface 与同名 schemastery schema。类型旁的默认值是 schema 默认；required(false) 表示可选且无默认。所有字段写在 cordis.yml 的 lcrd 行 config 下；patch 会整体替换该行 config，所以覆盖时要复述完整字段。

调整顺序：先确定运行时协议与校验器 → 再决定学习/文件流 → 再开演化 → 最后调门禁样本与统计。不要同时改 minGain、holdoutSize、repeats、significance，否则无法归因。

10.1 运行时 / 校验器

maxRetries number · 3

运行时终止预算

作用：连续校验失败达到该值后终止任务，后续工具调用（包括 lcrd_plan）被拦截并转人工。真实用户消息会重置计数。

联动：学习模式开启且达到阈值时暂停直接重试，由 maxLearningAttempts 接管；hook 的 deny/block/抛错独立计数，但同样以该值为上限；failedCheckConsumesRetry 决定引擎拒绝的检查是否消耗它。

风险：太小会让正常探索过早终止；太大浪费 token。生产建议 3–10；门禁/评测使用固定值，避免候选比较漂移。

pythonCommand string · "python"

Python 校验器启动命令

作用：verifier.kind = python 时用该命令启动固定模板脚本；Windows 需要可执行解释器或绝对路径。

联动：pythonTimeoutMs 控制超时；python 检查不受声明期区分度探测，非法检查只能在 post-execute 被判 FAIL。

风险：命令写错会让所有 python 校验失败；这是部署可信配置，不接受模型输入。

pythonTimeoutMs number · 30000

Python 校验超时

作用：解释器进程超过该毫秒数被 kill，判定 FAIL。

联动：受机器性能与检查复杂度影响；过短会把合法慢检查误判为失败。

verifierModel string · 可选

LLM 校验模型

作用：verifier.kind = llm 使用的模型 id；缺省使用 agent 自己的模型。

联动：evolveScanModel 缺省回退到它；LLM 校验每次多一次独立 API 调用。

风险：与主模型相同只提供“独立会话 + 固定提示词”的隔离，不提供跨账号/跨厂商隔离；要更强独立性请配置不同模型/账号。

logDir string · 可选

Flow 日志与 task-flow 根

作用：flow 日志根目录；默认插件包下的 lcrd-flow/。file-flow 的 task-flow 根是它的同级兄弟。

联动：evolvePolicyDir/datasetDir 缺省也相对它附近；把 logDir 放到 workspace 下可让 task-flow 根跟随，解决文件沙箱 workspace-write 拒绝。

风险：放在模型可写但非持久的位置会导致日志丢失；放在沙箱可见根之外会让模型无法写流程文件。

interaction "auto" | "auth" | "manual" · "manual"

人工交互策略

作用：控制审批提示与 ask_user_question。auto：审批自动拒绝，问题自动返回“请自主判断”；auth：审批交人工，问题保持交互；manual：两者交 UI answerer。

联动：auto 下审批策略是 never，因此演化只能提案不能 promote；evolvePromote: approval 仍然有效但无人可批。

风险：CI 用 auto 可避免挂起；需要人工放行时不能 auto。

failedCheckConsumesRetry boolean · true

引擎拒绝的检查是否消耗重试

作用：true 时 invalid-condition/eval-error 与真实失败共享 maxRetries（历史行为）；false 时它们由 invalidChecks 独立计数，任务预算只度量真实步骤结果。

联动：false 仍以 maxRetries 为上界；该计数出现在每条声明的 context 里。

用途：同一批任务跑 true/false 是对照实验，区分“模型不会写检查”与“任务没做成”。

rejectPresenceOnly boolean · false

拒绝仅存在性断言

作用：在声明期拒绝只断言存在/类型/非空、不钉字面量、也不读结构化字段的 assert 条件。

联动：区分度门禁（unbound、non-compiling、tautological）始终运行；这是额外的 form 检查，只作用于 assert。

风险：开启会提高声明门槛，可能迫使模型写更具体的检查；不会影响 python/llm。

declarationMaxHoldRate number · 可选 (0,1]

声明期 hold-rate 上限

作用：声明在探测矩阵上的最大通过率必须低于该值，否则声明被拒；缺省只记录 rate，不强制。

联动：只覆盖 assert；python/llm 没有可探测条件列表。开启后新 verdict 不会携带达到/超过上限的 rate；重新导出旧语料要考虑 withHoldRateReview。

风险：过严会让合法但宽松的检查在声明期被拒；先用 0.9 等宽容值观察。

10.2 学习模式

learningEnabled boolean · false

学习模式总开关

作用：开启后，连续失败达到阈值暂停直接重试，注册 lcrd_learn/lcrd_learn_verify 并要求学习轮；关闭保持纯回退/终止行为。

联动：learningThreshold、maxLearningAttempts、learningTools；学习期间 maxRetries 终止挂起。

风险：每轮增加 API/token；自评是模型自写标准，真正判定仍是重解的外生校验。

learningThreshold number · 5

进入学习模式的连续失败数

作用：连续失败达到该值且学习开启时进入学习模式。

联动：如果它大于 maxRetries，普通重试可能在进入学习前终止；生产应让阈值小于等于重试预算。

maxLearningAttempts number · 3

学习轮预算

作用：自评失败或重解失败消耗一轮；预算耗尽终止转人工。

联动：自评通过且重解成功会重置学习预算；无学习工具调用/无证据引用的自评通过被拒绝且不消耗轮次。

learningTools string[] · web_search/read/glob/grep/skill/subagent/web_fetch

学习阶段允许的工具

作用：学习阶段白名单工具不要求计划/校验直接放行；任务工具与 lcrd_plan 被拦截。

联动：至少一次白名单工具调用且引用登记证据，自评才可能通过；未注册名字无害。

风险：放入写工具会扩大学习阶段能力；建议只放只读知识获取工具。

10.3 文件式任务流

fileFlowEnabled boolean · false

文件式任务流开关

作用：开启后注入文件流协议段，插件创建并固定 taskflow 目录，模型维护 task.md/subtasks//progress.md，逐个执行子任务并最终整任务校验。

联动：fileFlowPathViolationsMax、workspaceRoot、fileFlowTools；task-flow 根是 logDir 的同级。

适用：只有 bash/字符串替换编辑器的极简部署；标准部署保持关闭，避免额外上下文与目录开销。

fileFlowPathViolationsMax number · 3

task-flow 路径违规上限

作用：读写当前任务目录之外但仍在 task-flow/ 下的路径会计数；达到上限终止为严重幻觉。引导性拒绝不计入。

联动：只有 fileFlowEnabled 时生效；与门禁的 pathViolations 指标相关。

workspaceRoot string · 可选

任务产物 workspace 绝对路径

作用：注入文件流协议文本，告诉模型任务产物应写到哪里；空则省略该行。

回退：session cwd → 部署 sandbox workspaceRoot → DSH_CWD → fs backend 工作根。

风险：部署工作区与上述来源不一致时必须显式设置，否则模型可能写进错误别名；沙箱 workspace-write 时它必须位于可写边界内。

fileFlowTools string[] · str_replace_editor/write/edit

受守卫的写工具

作用：守卫读取这些工具的 path 参数；读操作放行；shell 命令路径不检查。

风险：如果部署使用自定义写工具而没加入该列表，文件流路径约束不会被应用。

10.4 数据集 / 归因 / hooks

datasetExport "off" | "run" · "off"

自动导出开关

作用：run 时在 run 结束（agent disposal）把该 run 的 dataset/DPO 行追加到 datasetDir，不需要额外命令。

联动：datasetDir、attributionModule；进程内导出不需要 session log，文件级导出需要。

风险：开启会增加结束时的写盘开销；不动 run 的实时路径。

datasetDir string · 可选

数据集输出目录

作用：缺省为 flow 日志旁的 dataset/。写入 dataset.jsonl、relaxations.jsonl、runs.jsonl、dpo.jsonl、trainable.jsonl、needs_review.jsonl 等。

风险：append-only 语料会持续增长；不要在训练时把输出目录指到已提交的 corpus。

attributionModule string · 可选

领域归因 bundle

作用：模块路径/包名，default export 提供 classifyFailure、classifyRelaxationCause、classifyTrainability；加载后用于 dataset 行的分类。

联动：相对路径按进程 cwd 解析；不完整/非法 bundle 在启动时响亮失败；缺省保留日志启发式。

风险：分类函数应只读已记录字段，不应接触实时工具结果；错误分类会污染训练数据。

hooksModule string · 可选

部署策略 hook

作用：加载 checkPlan/checkResult 两个可选检查。checkPlan 可在声明后替换/拒绝计划；checkResult 可在校验后 block/terminate。

联动：替换计划对模型静默；替换仍过声明期门禁；拦截独立计数、以 maxRetries 为上限；deny 清除旧计划。

风险：hook 是受信部署代码，能看到计划与结果；非法替换会响亮失败。不要用它绕过外生校验。

10.5 演化核心

evolveEnabled boolean · false

策略演化总开关

作用：开启提案工具、policy store 访问、候选挂载、在线监控与 hard-out；关闭时插件是纯协议。

前提：evolveBenchmarkDir 必填，且组合 @deepseek-ai/dsh-skill；门禁 child 还必须加载 LCRD 插件（gate profile）。

evolvePolicyDir string · 可选

策略根目录

作用：存放 current.json、versions/、quarantine、holdout history、账本与 rejected-edits；缺省为 flow 日志旁的 policy/。

风险：必须对插件可读写；不要放进 holdout/hard-out 或模型可写根；备份它等于备份审计链。

evolveBenchmarkDir string · enabled 时必填

三层基准根

作用：读取 train.jsonl、holdout/*.jsonl、hardout/*.jsonl；每条 holdout 任务应有 reward 与可选 fixture。

边界：train 供模型提案；holdout 仅供门禁抽签；hardout 仅供封存审计。holdout/hardout 必须在模型可读根之外。

风险：路径写错/任务缺少 reward 会让门禁失败；benchmark 在门禁中被编辑会让整轮作废（digest 变化）。

evolveGateCommand string · "dsh"

门禁 child 启动命令

作用：启动 gate child 的可执行文件；缺省 PATH 上的 dsh。

联动：evolveGateArgs 在其后、harness flags 前插入；child 还接收 --profile、--patch、任务 anchor。

风险：命令必须能从 LCRD 进程环境解析；源码运行可能需要 node/tsx 包装。

evolveGateArgs string[] · []

Gate child 前置参数

作用：例如源码运行 ["--import","tsx/esm","apps/cli/src/bin.ts"]；被 prepend 到 harness flags 之前。

风险：不要把 profile/patch 写进这里；那些由 gate 自动追加。

evolveGateProfile string · "headless"

Gate child profile

作用：child 启动的 profile；必须挂载 LCRD 与 skill 服务。裸 headless 不含 LCRD，overlay 只按 id: lcrd 覆盖，不会插入行。

推荐：创建 lcrd-gate（dsh-base + dsh-headless + @deepseek-ai/dsh-experimental-lcrd-gate），并设置本项。

失败：profile 缺行时 probe 无 run.json，gate 以配置错误中止。

evolveGateRunTimeoutMs number · 900000

单个 gate child 超时

作用：child 超过该毫秒被 kill；也作为 reward timeout 的缺省来源。

风险：过短会误杀慢任务；过长会让坏 child 占住 gate 预算。

evolveCandidateVersion string · 可选

只由 gate overlay 写入

作用：把某一 policy 版本挂载为 active，同时关闭演化；部署通常不设置。

风险：手工设置会让正常会话固定到一个候选版本；只应出现在生成的 overlay。

10.6 门禁抽样与成本

evolveRepeats number · 3

每任务每侧重复数

作用：配对 n = evolveHoldoutSize × evolveRepeats；增加它会降低 detectability，但成本近似线性增加。

成本：gate child 次数 ≈ holdoutSize × repeats × 2 + 1（probe）。

风险：只看 repeats 不看 headroom 会继续做无意义的实验。

evolveHoldoutSize number · 5

每次抽中的 holdout 任务数

作用：从 holdout pool 抽多少任务；与 repeats 一起决定配对 n 和成本。

联动：pool 不足或 cooldown 让可选项不足时会响亮失败；扩 pool 不会自动降低 n 需求，只降低选题波动。

evolveHoldoutCooldown number · 3

holdout 轮换冷却

作用：最近该数量的 gate 抽中的任务暂时不合格，降低重复曝光。

风险：pool 很小时 cooldown 会让候选任务耗尽；这时应扩 pool 或降低 cooldown。

evolveHardoutAuditEvery number · 5 (0 disables)

封存审计周期

作用：每 N 次 promote 用 hardout 与 parent 在同一批 sealed 任务上对照；0 关闭。

联动：审计回退设置 promotionHeld，阻止后续 promote 直到 lcrd:policy clear-hold。

evolveGateMaxTokens number · 2000000

整轮 gate token 预算

作用：child 上报 token 累计超过该值即中止，status gate-aborted。

联动：evolveRunMaxTokens 是单 run 上限；evolveGateMaxWallMs 是墙钟上限。

evolveGateMaxWallMs number · 3600000

整轮 gate 墙钟预算

作用：超过即中止，status gate-aborted。

风险：长任务/慢模型需要更大预算；否则会在样本不足时中止。

evolveRunMaxTokens number · 200000

单 run token 上限

作用：写进 gate overlay，child 自身执行的上限；同时影响 gate 预算消耗。

evolveMaxTokenRegression number · 0.2

相对 token 回退上限

作用：candidate tokens 不得超过 baseline × (1 + 该值)；0.2 = +20%。

风险：门槛太松会让“更贵但无收益”的 skill 通过成本检查；仍需 gain 判定。

10.7 判定与统计

evolveMinGain number · 0.1

绝对增益门槛

作用：admission: reward 时比较 rewardRate；self-report 时比较 passRate。必须同时满足 headroom 与 detectability。

风险：基线 0.95 时最大增益 0.05，0.1 永远不可能；应换基准或降低门槛并增加样本。

evolveMaxSafetyRegression number · 0

允许的终止率绝对回退

作用：candidate terminatedRate - baseline terminatedRate 超过该值即拒绝。0 是零容忍策略。

注意：这是策略阈值，不是显著性检验；2 vs 0 可以拒绝而 Fisher p 不显著。

evolveMaxCheatRegression number · 0

允许的 speculative-cheat 绝对回退

作用：cheatRate 回退超过该值即拒绝；同样为零容忍策略，不是统计显著。

evolveAdmission "reward" | "self-report" · "reward"

准入指标

作用：reward 读取每个任务的 reward 命令（ground truth）；self-report 使用 agent 自己的校验通过率，仅适合 smoke。

联动：reward 下每任务必须有 reward，缺失即数据不完整；significance 要求 reward。

风险：self-report 可被 agent 自身逻辑影响，不能作为生产准入。

evolveSignificance "off" | "bootstrap" · "off"

额外显著性证据

作用：bootstrap 对配对 delta 做 bootstrap 区间；区间包含 0 则拒绝。要求 reward 且至少 2 对样本。

联动：evolveSignificanceAlpha；默认 off，因为小样本下可能拒绝真实增益。

建议：先跑 lcrd:policy noise，确认 detectability 后再开。

evolveSignificanceAlpha number · 0.05

双侧错误率

作用：bootstrap 与 detectability 的正态分位数使用；必须 0 < alpha < 1，否则 gate 配置错误。

风险：更小 alpha 更保守、需要更多样本；不要和 minGain 同时调。

evolveRequireDetectability boolean · true

样本分辨力门槛

作用：detectability > minGain 时拒绝准入，即使点估计过线。

联动：增加 repeats/holdout 或降低 minGain；关闭等于承认样本无法分辨门槛。

风险：关闭不是“加速”，而是放弃统计有效性。

10.8 提案与预审

evolveMaxProposals number · 2

每个任务边界的提案数

作用：限制同一任务内 lcrd_propose 次数；新用户命令重置。

evolveMaxSkills number · 8

单个提案的 skill 数上限

作用：超过拒绝；skill 名称必须 kebab-case 且不能占用现有名称。

evolveSkillMaxBytes number · 16384

单个 skill 正文字节上限

作用：超过拒绝；prevent prompt 膨胀。

evolveRationaleMax number · 2000

rationale 截断长度

作用：manifest/预审记录只保留该长度的 rationale。

evolveStaticScan "rules" | "rules+llm" · "rules"

静态扫描模式

作用：rules 是确定性规则；rules+llm 追加一次固定提示词模型扫描，输出不可用按 block。

联动：evolveScanModel 应独立于提案模型；扫描失败会阻断提案。

evolveScanModel string · 可选

rules+llm 的扫描模型

作用：缺省回退 verifierModel；规则要求与提案模型不同，否则扫描不是独立审查。

evolveBriefTopN number · 5

预审每节最多异常项

作用：静态 findings、unhealthy runs、quarantine 每节最多渲染该数量。

10.9 promote 与监控

evolvePromote "approval" | "auto" · "approval"

放行权威

作用：approval 询问审批服务，只有 allowed-once 放行；auto 不询问，仅供 CI。

联动：interaction auto 映射审批 never，因此无人值守只能提案；auto 仍受门禁/headroom/detectability 约束。

evolveRollbackWindow number · 10

在线监控窗口

作用：每个版本收集多少个已完成 run 形成窗口；首个完整窗口成为在线基线。

evolveRollbackMargin number · 0.2

在线终止率回退阈值

作用：后续窗口终止率高于该版本的在线基线超过该值，自动回滚并写 quarantine；cheat 回退默认零容忍。

风险：线上分布与 holdout 不同，不能拿门禁指标代替窗口基线。

10.10 参数组合速查

目标建议组合不要做
无人值守 smokeinteraction: auto, evolveAdmission: self-report把 self-report 结果当生产增益
生产门禁admission: reward, promote: approval, requireDetectability: true, significance: bootstrap（噪声数据支持后）auto + 小样本 + 高基线
教程/低预算holdoutSize: 2–5, repeats: 1–2, 关闭 significance用这类结果做发布决策

安全优先maxSafetyRegression: 0, maxCheatRegression: 0, 人工审批把零容忍阈值当显著性检验

12. 安全与信任边界

12.1 威胁模型

威胁防线残余风险
模型自我宣告完成/跳过校验任务工具必须先在 lcrd_plan 声明，post-execute 外生校验；失败阻断校验表达式本身可能写得太松；用区分度/ presence-only/ hold-rate 门禁
模型写恶意 skill静态扫描 + skill 只是数据 + 人工 promote启发式可被改写；需要人工审阅与后续监控
candidate 读取 baseline 产物每 run 独立 workspace + fixture 复制绝对路径/共享外部资源仍可能泄漏；holdout 隔离是部署责任
门禁伪造结果report/manifest/ledger 由引擎写；模型不能写运维误操作/磁盘损坏；用备份与 invariant
任意代码执行assert 受限语法；python 固定模板；不提供 command 校验器python 解释器本身与 reward 命令是受信部署代码
session 协议破坏不新增 session 事件；策略记录在 store旧构建看不到新策略；store 需独立备份

12.2 信任主体

  • 模型：不可信，只提供数据/声明/文本。
  • 部署/运维：可信；benchmark、reward、hooks、attribution、gate profile 都是部署代码/产物。
  • 审批人：权威；默认 promote 决定。
  • 插件/引擎：拥有判定、指针、账本、终止状态。

12.3 不做的事

  • 不在 agent 内启动训练；不把 checkpoint 写进 policy store（用 lcrd:checkpoint）。
  • 不提供模型可指定的任意 command verifier；不要为了“方便”打开这个面。
  • 不把 holdout/hardout 放在模型可读根内；插件只能校验不在 skill 根。

15. 限制与路线

  • 提示词上限：skill 只改程序性知识，不改权重；能力上限由提示词能买到的部分决定。
  • 统计功效：默认 5×3 是小样本；显著性默认 off；先 noise，再决定参数。
  • 基准饱和：基线 0.95 时 headroom 不足；换 0.3–0.7 的失败空间，而不是继续堆 skill。
  • 仪器失败：missing reward 不是 0 分；baseline/candidate 缺失必须修，不要静默丢对。
  • 在线 RSI：未实现；当前只有离线训练脚手架与 checkpoint 控制面。
  • 权重训练：需要 open-weight 模型 + GPU；API 模型不可训练。
  • 配置目录：Config 移到 config.ts 后生成器把 lcrd 归为 library；独立文档工具问题。
  • 搜索能力：单候选提案，无种群/归档/credit assignment；这是门禁层，不是搜索优化器。
